# 図の読み込み(Excalidraw・draw.io を、文章にして読む)

スキル `diagram-reader` の設計。使い方は [skills/diagram-reader/SKILL.md](../skills/diagram-reader/SKILL.md)。図を**作る**のは、別のスキル `excalidraw-diagram`([excalidraw.md](excalidraw.md))。

## 1. なぜ、このスキルがあるか

- **元のハーネスは、画像を認識できない LLM(ビジョンが切られた社内 LLM)のために、このスキルを作った。** GPT-5.4 mini 版では、モデルは画像を見られる。それでも、このスキルを使う。理由は 2 つ: ① Excalidraw・draw.io のファイルは、画像ではなくデータなので、`read` で開いても見た目は分からない。② 構造のデータから読む方が、矢印のつながり・分岐・レーンを、画像から読むより正確で、トークンも少ない。
- Excalidraw と draw.io の図は、中身が構造化されたデータ(箱・文字・矢印の座標と結合)なので、箱・矢印・枠(レーン)を**文章にして読める**。PNG の図には、できない(GPT-5.4 mini 版では、PNG・JPEG の図は、モデルが `read` で開いて見る)。
- **読むスキルは、形式ではなく目的でまとめた。** 「この図を説明して」と言うとき、利用者は形式を気にしない。入口が 1 つ(`describe`)で、形式は自動で判断する。作る側(Excalidraw 専用)の長い説明(仕様の書き方、配色の意味)は、読むだけのときには要らないので、別のスキルに分けた(読むたびに、作る側の説明を読み込む無駄を避ける)。

## 2. 構成

```
スキル diagram-reader
  scripts/diagram_cli.py      コマンド: describe / links。形式を自動判断
  scripts/load_excalidraw.py  Excalidraw (.excalidraw.md / .excalidraw、圧縮も) → 共通の中間形式
  scripts/load_drawio.py      draw.io (.drawio / .dio / .drawio.svg / .dio.svg、圧縮・複数ページも) → 共通の中間形式
  scripts/lzstring.py         Obsidian の圧縮データ (compressed-json) の展開
  scripts/diagram_model.py    共通の中間形式 → 文章 / Mermaid (箱・矢印・領域・レーン・流れの読み取り)

使う側: researcher (describe / links)、diagram (作った図の読み戻し)、メイン (describe は確認なしで許可)
コマンド: /read-diagram ファイル名
```

- 「共通の中間形式」は、Excalidraw の要素に似た辞書の並び(箱・文字・矢印の座標、結合、矢じり)。draw.io の図は、これに変換してから読む。そのため、**同じ図なら、どちらの形式でも、ほぼ同じ文章になる**(実際の「経費精算フロー」で、Excalidraw 版と draw.io 版が、同じ内容になった)。
- 標準ライブラリだけ(`.venv` が無くても、PATH の `python` で動く)。読み取り専用。書くのは `describe --out`(`.handoff/` の中だけ)。

## 3. 読み取りの工夫(手で描いた図でも読めるように)

- **文字を箱に割り当てる:** `containerId` があればそれ。無ければ、文字の中心を含む、いちばん小さい箱。
- **矢印の端を箱に割り当てる:** 結合があればそれ。無ければ、近く(28px 以内)の箱。箱の内側の短い線は、装飾として数えない。
- **領域とレーン:** 他の箱を含む大きな枠を領域とする。同じ形の領域が縦(または横)に並んでいれば、スイムレーンと判断する(外枠の中のレーンも)。レーンの見出しの箱は、領域の名前にする。
- **矢印のラベル:** 矢印に結び付いた文字、または、近く(24px 以内)にある、箱に属さない短い文字。
- **流れ:** 矢印をたどって段に分け、始点・終点・分岐(「はい: N4 / いいえ: N5」)・戻り(ループ)を出す。
- **折り返しの改行:** 日本語の折り返しの改行は、つなげる(「在庫あ / り？」を「在庫あり？」に)。箇条書き、文の区切り、空行は、「 / 」で区切る。
- 出力: 文章(既定)、または Mermaid(`--format mermaid`)。長いときは、行数の上限(既定 220)で切って知らせる。

## 4. draw.io の読み込み

- **ファイル形式:** `.drawio` / `.dio`(XML。先頭にコメントがあってもよい)、`.drawio.svg` / `.dio.svg`(SVG の `content` 属性に XML が入っている。Obsidian の diagrams.net プラグインが作る)。**この Vault の 21 個は、すべて、図の中身が圧縮されていた**(base64 → 生の deflate → URL エンコード)。標準ライブラリの `zlib` で展開する。複数ページにも対応(`--page`)。
- **座標:** 箱の座標は、親(swimlane などの入れ物)の左上が基準。絶対座標にしてから読む。
- **形:** `ellipse` / `terminator` は楕円、`rhombus` / `decision` はひし形、そのほかは長方形。円柱、書類、平行四辺形などは、形の名前を付ける(例:「データ(平行四辺形)」)。文字だけのセルは、文字として読む。画像(`shape=image`)は、数えるだけで、中身は読めない。
- **ラベル:** HTML のラベルを、文字にする(`<br>` は改行、`<div>` / `<p>` の終わりは段落の区切り)。矢印のラベルは、矢印の `value` と、矢印の子の `edgeLabel` の両方を読む。
- **矢印:** `source` / `target` を結合先にする。矢じりは、`endArrow` / `startArrow` から決める(`none` は線)。つながっていない矢印は、`sourcePoint` / `targetPoint` と近さで割り当てる。
- **`object` / `UserObject`** の `label` も読む。非表示のセル(`visible="0"`)は読まない。
- **安全:** DTD と実体の宣言を含む XML は、処理しない。展開後の大きさ(30 MB)、セルの数(1 万個)に上限がある。

## 5. 確認できたこと(自宅の Mac)

- **この Vault の図 169 個**(Excalidraw 148 個、draw.io 21 個。Excalidraw の圧縮されたもの 55 個、draw.io の圧縮されたもの 20 個を含む)を、コマンドの入口(`describe` の文章と Mermaid)から、すべて例外なく読めた。最も遅い図(約 1 MB)でも 0.4 秒。
- **実物のスイムレーン図とフローチャート**(Excalidraw 版と draw.io 版の両方)で、箱、矢印、分岐の「はい / いいえ」、ループ、レーンの所属を、正しく読めた。draw.io の、文章が多い図(1 つの箱に 5 行、矢印のラベルが複数行)でも、読めた。
- 圧縮データの展開は、Obsidian のプラグインが実際に保存した Excalidraw の図と、draw.io が実際に保存した `.drawio.svg` で確認した。
- テストは、Excalidraw と draw.io の図を、テストの中で組み立てて読む(圧縮、SVG、複数ページ、スイムレーン、HTML のラベル、不正なデータ、DTD、大きすぎる図、など)。作った図を読み戻すテストも、ここにある。

## 6. 限界と、確認できていないこと

- **画像の図は読めない**(PNG、JPEG、`.drawio.png`)。図の中に貼られた画像と、手書きも、中身は読めない。
- 読み取りは、手で描いた図の多くの癖に対応したが、**推測を含む**(文字の割り当て、レーンの判断、矢印の端)。スキルは、「注意」の行を、説明に反映させるよう指示している。
- draw.io は、通常の図形・矢印・スイムレーンに対応。表(`table`)、入れ子の複雑なレイアウト、レイヤーの切り替えは、箱の並びとして読むだけ。
- **まだ確認していないこと:** 会社の Windows での動作、会社の draw.io / Excalidraw のバージョンの違い、**会社の LLM が `describe` の出力から、図を正しく説明できるか**。会社での確認は [company-checklist.md](company-checklist.md) の 13。

## 7. 今後の候補

- draw.io の図を**作る**(Excalidraw と同じ仕様から)。必要になったら、`diagram-reader` ではなく、作る側のスキルに足す。
- `.drawio.png`(PNG のメタデータに XML が入っているもの)の読み取り。
- Mermaid のコードブロック(ノートに直接書かれたもの)は、すでに文章なので、読む必要はない。
