## 前提

- 実行: 作業フォルダのまま `<スキルのフォルダ>\run.bat 引数`(Mac・Linux は `run.sh`)。`cd` しない。
- Vault は、いまのフォルダから上へたどって見つかる `.obsidian` のあるフォルダ。Vault の決まり(フォルダ、frontmatter、リンク)は、Vault の `AGENTS.md` に従う。
- 書くのは Vault の中だけ。ドットで始まる場所(`.obsidian` など)には書かない。**削除と上書きはしない。**
- **日付と時刻は推測しない。** 必ず `run.bat today` の値を使う(「来週の金曜」なども、`today` の一覧から選ぶ)。

## 守ること

- 保存・修正は、「保存して」「メモして」「直して」と頼まれたときだけ。「これで進めよう」「決めた」は、保存の依頼ではない(例外: 下の「知識ノート」は、教わったら頼まれなくても保存する)。承認は待たない。
- 書くのは、ユーザーが決めた内容だけ。会話に出ていないことを足さない。
- 「」は、原文どおりの引用だけに使う。
- 未レビューの AI のまとめ(`10_summary/`、`ai_reviewed` が `true` でないノート)を出典にしない。原典を読んで、原典をリンクする。
- 複数のノートを変えるときは、そのまま進め、最後に一覧を報告する。

## 新しいノートを保存する

1. 題名とタグは、書かれていなければ自分で決める(聞き返さない)。保存先は、指定が無ければ今日のフォルダー。聞くのは、内容そのものが決まっていないときだけ。
2. `run.bat today` で日付を確かめる。
3. **関連するノートを探す(必ず)。** 中心の語(人・案件・製品・用語)を 3〜8 個で探す。

   ```
   run.bat related 語1 語2 語3
   ```

   - 本文が本当に関係するものだけを選ぶ(目安 3〜8 個)。リンクは、表に出た `[[ ]]` の形のまま使う。**表に無いノートはリンクしない。**「※ AI の未レビューのまとめ」はリンクしない。
   - 語を変えて 1〜2 回探しても無ければ、リンクなしで保存し、報告に「関連するノートは見つからなかった(探した語: …)」と書く。
4. **既存のタグを探す(必ず)。** そのまま `obsidian tags counts sort=count` を実行する(長ければ Windows は `| findstr /i 語`、Mac は `| grep -i 語`)。エラーか出力が無ければ、`obsidian` を探さず、手順 3 の表のタグから選ぶ。
   - 関連ノートのタグと、語の言い換え(日本語・英語・略称)で探す。既存のタグを綴りどおりに使う。2〜5 個。階層(`a/b`)は使わない。
   - 合うものが無いときだけ新しいタグにし、報告に「新しいタグ: X(理由)」と書く。
5. 本文を `.handoff/draft_<話題>.md` に書く。**frontmatter は書かない**(自動で付く)。である調、結論を最上部に。関連ノートは、本文のその語の所に `[[ノート名]]` で入れ、入らないものは末尾の `## 関連` に `- [[ノート名]] — 理由(1 行)` で並べる。
6. 保存する。注意が出たら、下の「注意が出たとき」で直す。

   ```
   run.bat new-note --title "題名" --body-file .handoff/draft_話題.md --tags タグ1,タグ2
   ```

   - 今日のフォルダー以外は `--dir フォルダ`(Vault からの相対)。
   - ガントのタスクとつなぐノートは `--gantt-id タスクID`(名前が `題名【ID】.md` になる)。タスク側は、スキル `app-ecosystem` の `task-link` でこのノートを指す(タスクが無ければ先に `task-add`)。
7. 報告する: `[[ノート名]]` とパス、リンクしたノート(無ければ探した語)、付けたタグ(新しいタグは理由)。同名があると `_2` が付く。

## 知識ノート(`99_knowledge/`)

資料に無く、ユーザーに聞いて教わった知識(用語・略称・社内の決まり・案件の事情)を、`99_knowledge/` に **1 話題 1 ノート**で置く。ユーザーの決定や予定(「〜することにした」「これで進めよう」)は、知識ではない(保存しない)。

1. 書くのは、ユーザーが言ったことだけ。秘密(パスワード・キー)と私生活のことは書かない(理由を伝える)。人のことは、スキル `people` へ。
2. 題名は、話題の短い名詞(例: `経費精算の締め日`)。
3. **同じ話題のノートを探す。** `run.bat related 語1 語2`(言い換え・略称も)で、`99_knowledge/` のノートを見る。**`99_knowledge/` の外のノート(`01_data/` など)は、同じ話題でも直さない**(人のノート。新しい知識ノートからリンクする)。
4. **あれば、直す。** `edit` で該当の節に最小の変更を足す。食い違えば、新しい言葉に合わせる(報告に前後を書く)。**`backup` と `mark-edit` は要らない**(Git で管理しているため)。
5. **無ければ、作る。** 上の手順 4・5 のとおりタグと本文を用意して保存する。

   ```
   run.bat new-note --title "話題" --body-file .handoff/draft_話題.md --tags タグ1,タグ2 --dir 99_knowledge
   ```

6. 保存したら報告する: 新規か更新か、`[[ノート名]]`、書いた内容の要点。
7. `99_knowledge/` のノートは、教わったことだけなので、根拠にしてよい。

## 既存のノートを修正する

1. 対象を読む。依頼が曖昧でも、読み取れる範囲で直す(聞くのは、直し方が大きく分かれるときだけ)。
2. **直す前に、必ずバックアップする。** 写しが `.handoff/backup/` にできる。

   ```
   run.bat backup "01_data/2026/11/07/対象.md"
   ```

3. `edit` で、最小の変更だけを入れる。frontmatter(特に `created`)、見出しの構成、`[[リンク]]`・`![[埋め込み]]` の形、Dataview・Templater のコードは、頼まれない限り変えない。`.excalidraw.md` は編集しない。
4. **直したら、必ず `mark-edit` を付ける**(`ai_edited` に日時、`ai_reviewed: false`)。人がレビュー漏れを確かめるための印で、直したノートは根拠に使ってよい。

   ```
   run.bat mark-edit "01_data/2026/11/07/対象.md"
   ```

5. 読み直して確かめる。Vault が Git にあれば、スキル `app-ecosystem` の `review <ノート>` で、人が差分を見る URL を得る。
6. 報告する: パス、変更前と変更後、バックアップのパス、差分の URL(Git のとき)、「確かめたら `ai_reviewed` を ✓ に」。

名前の変更・移動は、このスキルではなく、スキル `obsidian-cli` の「整理する」で行う。

## 議事録を作る

会議のメモから、議事録を作る(`/meeting-notes`。Vault の外のメモにも使える。スクリプトは使わない)。

1. メモを読む。日時・参加者・議題は、分かる範囲で拾い、分からなければ「不明」。参加者と担当者は、スキル `people` の `who` で引き、氏名と所属で書く(人物ノートが無い人は、メモの書き方のまま。保存した後に `people` の手順で聞く)。
2. 次の形で書く。メモに無い決定事項・担当・期限を作らない(無ければ「不明」)。

   ```markdown
   # 議事録: (会議名)

   - 日時:
   - 参加者:

   ## 決定事項
   - 

   ## ToDo
   - [ ] (内容) / 担当: / 期限:

   ## 論点・未決事項
   - 

   ## 議論の要約
   - 
   ```

3. 聞き返さずに保存する。保存先は、指定が無ければ、元のメモと同じフォルダの `議事録_<会議名>.md`(あれば `_2`)。元が会話に貼られたメモなら、Vault の中では今日のフォルダーに `new-note` で、Vault の外では `.handoff/` に書く。元のメモは書き換えない。パスと要点を報告する。

## 注意が出たとき

- `new-note` の「注意:」は、その文のとおりに直す(タグとリンクは `edit` で)。直さずに残したもの(新しいタグ、見つからなかった関連ノート)は、報告に書く。
- 「Vault が見つかりません」は、作業を止めて報告する。「ドットで始まる場所」「.gitignore」の注意は、回避せず、人に伝える。

- `related` の表: `[[リンクの形]]`、パス、点数(名前 3・タグ 2・本文 1)、一致した語と場所、タグ、一致した本文の 1 行。語の一部でも一致する。意味の近さは見ない(言い換えは、語を変えて探す)。
- `unreviewed`: 人のレビューが済んでいない AI のノートと、印の付け忘れの疑い。自分が直したものの疑いには `mark-edit` を付ける。
- `ai_reviewed` を自分で ✓ にしない。

できなかったことは、そのまま報告する。別の方法で回避しない。
