## 前提

- Excalidraw と draw.io の図は、中身が構造化されたデータなので、箱・文字・矢印・枠(レーン)を、文章にして読める。**これらの図を読むときは、必ず `describe` を使う**(画像として眺めるより、矢印のつながりと文字を、正確に読める)。
- この環境の LLM は、画像を見られる。**画像(PNG・JPEG・GIF・WebP)の図は、`read` で開いて見る**(このスキルのスクリプトは使わない)。見て読み取れない小さな文字や、あいまいな矢印は、未確認と書く。
- 読める形式: Excalidraw(`.excalidraw.md`、`.excalidraw`。圧縮されたものも)、draw.io(`.drawio`、`.dio`、`.drawio.svg`、`.dio.svg`。圧縮されたもの、複数ページも)。形式は、自動で判断される。
- **`describe` で読めないもの:** 画像(PNG、JPEG)の図、`.drawio.png`、図の中に貼られた画像と手書き(「中身は読めません」と出る)。画像のファイルがあるものは、`read` で開いて見る。
- 実行: 作業フォルダのまま `<スキルのフォルダ>\run.bat 引数`(Mac・Linux は `run.sh`)。`cd` しない。
- **読み取り専用。** 読めるのは、いまのフォルダと Vault の中だけ。書くのは `--out`(`.handoff/` の中だけ)。図は変更しない。

## 使い方

```
run.bat describe 図_申請フロー.excalidraw.md
run.bat describe 経費精算.drawio.svg
run.bat describe 経費精算.drawio.svg --format mermaid
run.bat describe 設計.drawio --page 2
run.bat links 報告.md
```

- `describe`: 図を文章にする。手で描いた図(文字が箱に結び付いていない、矢印が結び付いていない)も読める。
- `links`: ノートに埋め込まれた図(`![[名前.excalidraw]]`、`![[名前.drawio.svg]]`)の場所を探す。**ノートを読んで、図の埋め込みを見つけたら、中身が分からないまま進めず、`links` → `describe` で読む。**
- `--format mermaid`: Mermaid の文にする。フロー図・スイムレーンの理解に向く(LLM が Mermaid を読み慣れている)。
- `--page`: draw.io の読むページ(番号か名前)。省略すると、全ページを順に読む。
- `--full`: 長い文字を省略しない。`--max-lines`: 出力の行数(既定 220)。大きな図は、`--out .handoff/図の説明.md` に書いて、必要な部分だけを読む。

## 出力の読み方

| 節 | 内容 |
|---|---|
| 概要 | 箱・矢印・領域の数。種類の推定(スイムレーン図 / 矢印でつないだ図 / 箱の配置図)。画像や手書きがあれば、そう書かれる(**`describe` では中身は読めない**) |
| 領域 | 大きな枠(R1、R2…)と、含む箱。スイムレーンは「(レーン)」と出る |
| 箱 | N1、N2…。上から下、左から右の順。文字、形・色、所属する領域、位置(何段目・左から何番目)。draw.io の円柱・書類などは、形の名前で出る |
| つながり | `N1「A」 → N2「B」 (ラベル)`。`→` は矢印、`↔` は双方向、`—` は矢じりの無い線。`[点線]` は破線 |
| 流れの推定 | 矢印をたどった段、始点・終点、分岐(`はい: N4 / いいえ: N5`)、戻り(ループ) |
| 矢印につながっていない箱 | 注記や凡例のことが多い |
| 箱に属さない文字 | 見出し・注記 |
| 色の使い分け | 色ごとの箱。色に意味がある図(赤=異常、など)では、凡例とあわせて解釈する |

## 説明のしかた

- 説明するときは、**N 番号ではなく、箱の文字**で書く(ユーザーは N 番号を知らない)。流れ → 分岐 → 担当(レーン)→ 注記の順に、簡潔に。
- 「注意: 箱につながっていない矢印・線が N 本」は、読み取れなかった矢印がある、という意味。説明に、そう書く。
- 「画像 N 個(中身は読めません)」「手書き N 個」があれば、その部分は、未確認と書く(貼られた画像のファイルが Vault にあれば、`read` で開いて見てよい)。
- 位置(何段目・左から何番目)は、見た目の配置の手がかり。矢印のつながりと食い違うように見えるときは、矢印を優先する。
- 推測で補わない。図に書かれていないことは、書かれていないと答える。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| 「読んでよい場所の外です」 | 回避せず、そのまま報告する |
| 「対応していない形式です」 | 画像(PNG など)の図は、`describe` では読めない。`read` で開いて見る |
| 「図のデータ (## Drawing の下の json) が見つかりません」 | Excalidraw のファイルではない。報告する |
| 「SVG に draw.io のデータ (content 属性) がありません」 | draw.io が作った SVG ではない(普通の SVG)。報告する |
| 「圧縮された図のデータを展開できません」 | ファイルが壊れている。報告する(直そうとしない) |
| 「展開すると大きすぎる図です」「DTD / 実体の宣言が含まれている」 | 安全のため処理しない。報告する |
| 「ページが見つかりません」 | メッセージにある、あるページから選ぶ |

できなかったことは、そのまま報告する。別の方法で回避しようとしない。
