description: 登場人物(自分も)を覚える。依頼や資料に人が出たら必ず引く(who)。人物ノートとメールの集計、インタビューして人物ノートに保存する手順

## 前提

- 実行: 作業フォルダのまま `<スキルのフォルダ>\run.bat 引数`(Mac・Linux は `run.sh`)。`cd` しない。
- 人物ノートは、Vault の `05_people/` に 1 人 1 ノート。メールの集計(件数、最後の連絡、よく一緒の人、最近の件)は、`outlook-mail` のキャッシュから毎回出る。
- Vault は、`config.local.json` の `vault`、無ければいまのフォルダから上へたどって探す(`config.local.json` が無いのは普通。ほかの場所を探さず、そのまま実行する)。

## 守ること

- **書くのは、業務の事実だけ:** 氏名、読み、会社・部署、業務のメールアドレス、役割、決裁の範囲、自分との関係、仕事の進め方の決まり、やり取りの経緯(日付と出典つき)。
- **書かない:** 電話番号、住所、私的な連絡先、私生活、家族、健康、思想・信条、**人物の評価**(能力・性格・好き嫌い)、メール本文の転記。言われても書かず、理由を伝える。
- 会話・資料・メールに出ていないことを足さない。人物ノートは、このスクリプトだけで書く(手で書き換えない。削除しない)。
- **AI が作った人物ノートは未レビュー。** `who` で「[未レビュー…]」と出た内容は、「(未レビュー)」を付けて手がかりとして示す。メールの集計は事実なので、そのまま使ってよい。

## 引く

```
run.bat who 山田 taro.yamada@abc.co.jp
run.bat who --mail m1a2b3c
run.bat who --self
run.bat candidates --since 90 --min 3
run.bat check
```

- `who 名前`: 氏名・呼び方・アドレスの一部でよい。人物ノートに無ければ、メールのキャッシュから探す。
- `who --mail ID`: そのメールの差出人・宛先・CC をまとめて引く(メールを読む前に)。
- `who --self`: 自分のノート(返信の下書きの前に。文体・署名)。
- `candidates`: やり取りが多いのに人物ノートが無い人。`check`: 重複・古い・未レビューなどの点検。
- 「判別できない」(同じ表示名が 2 人)と出たら、人物ノートの `aliases` を見直してもらう。

## 書く

```
run.bat new "山田 太郎" --kana "やまだ たろう" --email taro.yamada@abc.co.jp --alias 山田さん --org "ABC 株式会社 設計部" --role "見積の窓口" --relation 客先 --point "見積は部長決裁" --checked
run.bat new "自分の氏名" --self --role "設計担当" --point "返信は丁寧語。署名は「設計部 氏名」"
run.bat set 山田さん --role "仕様の窓口" --point "図面は PDF で送る" --checked
run.bat memo 山田さん "改訂図は PDF で送る決まり" --source "RE: B 案の図面"
```

- `--relation`: `自分`・`上司`・`同僚`・`社内`・`客先`・`協力会社`・`その他`。
- `--checked`: ユーザーに確かめた(今日の日付が入る)。インタビューで確かめたときに付ける。
- `--point`・`--alias`・`--email` は何度でも書ける。`set` は足すだけ(消す・直すのは人)。
- `outlook` の返答の「人物メモの案」は、そのまま `new`・`set`・`memo` で書く(`--source` にメールの件名)。
- 保存は承認を待たない。書いた内容を報告する。

## ほかの作業で人が出たとき

1. 依頼や資料に人が出たら、**答える前に** `who 名前`(メールなら `who --mail ID`)で引き、答えでは「山田さん(客先・見積の窓口)」のように補う。
2. **人物ノートが無い人**は、依頼に答えた後で、下の「インタビュー」の 3 の形で聞く(1 人 3 問まで、3 人まで。多ければ関わりの深い順で、残りは名前だけ示す)。資料で分かったことは聞かず、おすすめの答えにする。
3. 答えをもらったら、`new … --checked` で登録して報告する。「登録しない」「もういい」と言われたら、聞かない。
4. 「Vault が見つかりません」と出たら、引かずに作業を続け、「未確認」に書く(人物のことを頼まれたときだけ、止めて報告する)。

## インタビュー(`/people`)

**事実は自分で調べ、判断はユーザーに聞く。**

1. **対象を決める。** 名前の指定があれば、その人だけ。無ければ `who --self` を見て、自分のノートが無ければ自分から。あれば `candidates` の上位(5 人まで)と、`check` で確かめた日が古い人。
2. **聞く前に調べる。** `who 名前` と、スキル `file-finder` の `content` で名前を探し、所属・役割・担当の件を拾う(出典を控える)。分かることは聞かない。
3. **1 人ずつ、3 問まで聞く。** 調べたことを 1〜2 行で示し、おすすめの答えを付ける。

   ```
   👤 田中 次郎(jiro@xyz.co.jp、直近 90 日で受信 3 通、件: 打合せ / 議事録)

   ❓ Q1 - 関係: 客先・協力会社・社内のどれですか
   ➡️ おすすめ: 協力会社(アドレスが社外で、件名が打合せ・議事録のため)

   ❓ Q2 - 役割: どの件の、どんな窓口ですか
   ➡️ おすすめ: (分からないので、ご記入ください)
   ```

   - 「はい」でおすすめを受け入れられる形にする(「1 はい、2 は B の窓口」と答えられる)。
   - おすすめの理由は、`who` や資料で確かめたことだけ(上の例の理由を写さない)。資料で答えが分かる問いは、聞かずに 1 行目に書く。
   - 自分のインタビューでは、氏名、役職・担当、呼ばれ方、返信の文体と署名、よくやり取りする相手を聞く。
   - 「この人は登録しない」で飛ばす。「もういい」で止める。
4. **保存する。** `new`(または `set`)を `--checked` で。「書かない」に当たる答えは書かず、そう伝える。
5. **報告する。** 作った・直したノートの一覧と、「Obsidian で確かめ、`ai_reviewed` に ✓ を付けてください(✓ までは根拠にしません)」。

電話番号や郵便番号のような文字列があると、スクリプトは書かずに止まる。
