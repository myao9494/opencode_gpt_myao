# Vault のルール

この Vault は、第二の脳として育てていく Obsidian のノート集です。ノートは Markdown で書かれています。

## スキルとエージェントを先に使う

自分の知識や手作業で済ませる前に、合うスキル(`skill` で読み込む)を使う。**迷ったら使う。** 子(エージェント)は、読む量が多い重い作業だけ。共通ルール(答える・作業する前にスキル `file-finder` で探す、人は `people` の `who` で引く、教わったことは `99_knowledge/` に保存する)は、この Vault でも同じ。**調査は、1 回で答えまで出す**(見つけたファイルは、聞かずに読む)。

| 依頼 | 使うもの |
|---|---|
| ファイルを探す、「〜はどこ」、資料の 1 か所で答えが出る問い | `file-finder`(自分で探して読む) |
| 「〜について調べて」 | 自分で探して読む。Word・Excel・PowerPoint の分析、10 以上のファイル、10 ページを超える PDF、画像 4 枚以上は `researcher` |
| 計算・単位の換算・判定(暗算しない) | `calc-check` |
| 手順書・マニュアル・長い資料を書く / 依頼が曖昧 | `doc-writing` / `interview` |
| 書いた文を整える | `yomiyasu`(長い文書は `polish`) |
| ノートに保存する・直す / 議事録 | `vault-notes`(議事録は、その「議事録を作る」) |
| ノートを開く・整理する(名前の変更・移動)・リンクやタグを調べる・プラグインのコマンドを実行する | `obsidian-cli`(公式の Obsidian CLI。名前の変更・移動でリンクが自動で直る) |
| 図を作る / 図を読む | `diagram` / `diagram-reader` |
| タスク・期限、Git の差分、自作のアプリ | `app-ecosystem` |
| メール・予定 | `outlook`(受信と送信のキャッシュから探すので、期間や条件を聞き返さずに任せる) |
| 登場人物(自分も)を引く・覚える | `people`(覚えるのは `/people` のインタビューで) |
| Web を読む / Web の操作の自動化 | `browser` / `browser-session` |

## Vault の構成

| フォルダ | 役割 | 触り方 |
|---|---|---|
| `01_data/` | ノート本体。`01_data/年/月/日/` の形で、作った日ごとのフォルダに置く | 依頼されたノートだけ変更してよい |
| `01_data/000_適宜移す/` | 仮置き場(`00_inbox`、`90_資料`、`99_日次記録` など)。あとで整理する | 頼まれたら、`obsidian-cli` で整理してよい。頼まれなければ動かさない |
| `01_data/common_image/` | 共通で使う画像 | 触らない |
| `02_MOC/` | 目次ノート(MOC) | 依頼されたときだけ変更する |
| `05_people/` | 人物ノート(1 人 1 ノート。自分も)。業務の事実だけを書き、電話番号・私生活・人物の評価は書かない | スキル `people` で作る・足す。直接は書き換えない |
| `03_Dataview/` | Dataview で作った点検用のノート(空のファイル、同名ファイル、無題のファイルなど) | 依頼されたときだけ変更する |
| `04_pptx/` | Markdown から PowerPoint を作るためのビルド用ファイルと出力 | 触らない |
| `10_summary/` | AI が作った要約。名前は `元のノート名_summary.md` | 新しい要約は、ここに別のノートとして作る |
| `11_common_prompt/` | AI に渡す共通の指示 | 触らない |
| `00_templates/` | Templater のテンプレート | 触らない |
| `70_gantt_csv/` | ガントチャートから出力された CSV と差分 | 触らない(自動生成) |
| `80_script/` | Templater などのスクリプト | 触らない |
| `99_knowledge/` | ユーザーに聞いて得た知識(用語・社内の決まり・案件の事情など)。**1 話題 1 ノート**。同じ話題が出たら、そのノートを直す。ユーザーが言ったことだけを書く | スキル `vault-notes` の「知識ノート」で、頼まれなくても作る・直す。AI が書いたノートでも、根拠にしてよい |
| `90_batch/` | 補助のバッチファイル | 触らない |
| `Excalidraw/`、`Analysis/`、`Parts/`、`Media/` | 図と 3D CAD 関係の成果物 | 触らない |
| `scratch/`、`temp/` | 一時的な作業用 | 中身は残る前提にしない |
| `.obsidian/`、`.smart-env/`、`.excalidraw-cache/`、`.claudian/`、`.trash/` | Obsidian とプラグインの設定、キャッシュ、ゴミ箱 | 触らない |
| `.handoff/` | サブエージェントが詳細の結果を書く使い捨てのフォルダ。ドットで始まるので Obsidian には表示されない。Vault の `.gitignore` に入れておく | サブエージェントの結果を読むときだけ読む。ノートとしては扱わない |

## ノートの書き方

- 新しいノートの先頭には、次の frontmatter を付ける。

  ```
  ---
  created: 2026-01-01 09:00:00
  tags:
  ---
  ```

  `created` には、作った日時を `YYYY-MM-DD HH:mm:ss` の形で書く。
- **AI の印:** ハーネスが作ったノートには `ai_generated: opencode` と `ai_reviewed: false`、直したノートには `ai_edited`(日時)と `ai_reviewed: false` が付く。人が確かめたら `ai_reviewed` を ✓ にする。AI は、作ったノートを ✓ まで根拠にしない(直したノートと `99_knowledge/` は根拠にしてよい)。印の無いノートは人のノート。`10_summary/` は印が無くても AI の要約。未レビューの一覧は、ハーネスに「レビューが残っているノートは?」と聞く。
- 文章は「である調」で書く。検討や検証のノートは、結論・結果を最上部に書く。
- タグは、既存のものを綴りどおりに使う(`obsidian tags counts sort=count`)。階層(`a/b`)は使わない。
- リンクは `[[ノート名]]`。新しいノートには、`vault-notes` の `related` で見つけた関連ノートへのリンクを入れる(見つからないノートはリンクにしない)。
- 画像や図の埋め込みは、`![[ファイル名]]` の形に保つ。画像のパスや `<img>` タグに書き換えない。
- 元のノートの frontmatter と見出しの構成は、依頼がない限り変えない。
- ファイル名に `\ / : * ? " < > |` は使わない。
- 新しいノートは、指定が無ければ、聞き返さずに今日の `01_data/年/月/日/` に作る。

## ノートの保存・修正

- 保存と修正は、スキル `vault-notes` で、頼まれたときだけ(`99_knowledge/` の知識ノートは、教わったら頼まれなくても)。開く・名前の変更・移動・プラグインのコマンドは、スキル `obsidian-cli`。

## 図(Excalidraw・draw.io)

- 図(`.excalidraw.md`、`.drawio`、`.drawio.svg`)は、スキル `diagram-reader` の `describe` で文章にして読む。画像の図は `read` で見る。ノートに図の埋め込みがあれば、中身を読んでから説明する。
- 図を作るのは、サブエージェント `diagram`(`/diagram`)。名前は `図_話題.excalidraw.md`、保存先は指定が無ければ対象のノートと同じフォルダ。draw.io の図は読むだけ。
- 既存の図は上書きしない(直すときは、新しい図として作り直す)。

## 触らないもの

- 上の表で「触らない」とされたフォルダの中。
- `.excalidraw.md` のファイル。中身は圧縮されたデータで、文章として編集すると壊れる。読んで内容を説明するだけにする。
- 画像、PDF、CAD などの添付ファイル(`.md` 以外)。削除しない。名前の変更・移動は、`obsidian-cli` でだけ行う(埋め込みが直る)。
- Templater や Dataview のコードブロック(`<% %>`、`<%* %>`、` ```dataview `)。依頼がない限り書き換えない。

## 名前の変更・移動・削除

- **名前の変更・移動は、スキル `obsidian-cli` の「整理する」の手順で行う**(リンクが自動で直る)。シェルの `move` やファイルの道具では動かさない。
- **削除はしない**(人が行う)。不要に見えるもの、空のフォルダは、報告に書く。

## 作業のしかた

- **返答でノートを示すときは、`[[ノート名]]` の形で書く**(Claudian のチャットでは、クリックで開けるリンクになる。パスだけでは開けない)。同じ名前のノートが複数あるときは、フォルダつき(`[[01_data/2026/11/07/ノート名]]`)にする。図は `[[図_話題.excalidraw]]` のように `.md` を除いた名前。Vault に実在するノートだけをリンクにする(無いノートはリンクにならない)。コードブロック(` ``` `)の中と、表の中の `[[名前|別名]]` は使わない(リンクにならない・表が崩れる)。
- 要約や整理は、ノートに書かれていないことを足さず、出典を示す。結果は、元のノートを上書きせず、別のノートにする(頼まれたときを除く)。

## Vault のカスタマイズを直すとき

(スクリプトやプラグインのソース、`docs/` がある Vault だけ)

- 仕様書は `docs/` にある。仕様書と実装が食い違っていたら、実装を正として、仕様書を直す。
- Templater のスクリプトの本体は `80_script/register_custom_commands/` にある。ファイルを追加・改名したら、`00_templates/RegisterCustomCommands.md` の一覧も直す。
- プラグインのソース(`.ts`)を変えたら、`npm test` と `npm run build` で確かめる(`node_modules` が無いときは、`npm install` はしない。会社の決まりで、`pip` 以外のパッケージは入れないので、人に頼む)。ビルド済みの `main.js`(Git で管理している)は、直接編集しない。
- スクリプトを書くときは、Python(`pip install` が使える)か、Node.js を使う。
- `*.excalidraw.md` に仕様のコメントを書くときは、frontmatter の直後に書く。前に書くと、Obsidian が図として開けなくなる。
